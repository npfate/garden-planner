# Правила работы над проектом GardenPlanner Pro

## Общие правила
- Используй **TypeScript strict mode** всегда
- Пиши код полностью, без сокращений типа "// остальной код здесь"
- Перед созданием/изменением файла — коротко объясни, что делаешь
- Если не уверен в решении — спроси меня, не выдумывай
- Если видишь проблему в моем ТЗ — предложи улучшение

## Стиль кода
- Функциональные компоненты React с хуками
- Именование файлов: **PascalCase** для компонентов (YearSwitcher.tsx), 
  **camelCase** для утилит (formatDate.ts)
- Именование переменных: **camelCase**
- Именование типов/интерфейсов: **PascalCase**
- Комментарии только там, где логика неочевидна
- CSS-классы в гибридном подходе:

### Основной подход:
- **UI компоненты** (кнопки, панели, формы): TailwindCSS
- **Уникальные элементы** (canvas, иконки растений): CSS Modules
- **Глобальные стили**: минимум, только сброс и шрифты

### Правила:
1. Для кнопок, инпутов, модалок используй только Tailwind утилиты
2. Для canvas и кастомных компонентов создавай .module.css файлы
3. Если не уверен — используй Tailwind, потом можно переделать
4. Все кастомные стили должны быть в отдельных файлах, не в globals.css

## Архитектурные принципы (Future-Proof)
- **Закладывай расширение:** При создании TypeScript интерфейсов (например, `Tree`, `GardenObject`) сразу включай поля для будущих фич (например, `history: Record<number, { harvest?: number, rating?: 'like' | 'dislike' }>`, `varieties: string[]`), даже если на Этапе 1 мы их не используем в UI.
- **Не хардкодь:** Избегай жесткой привязки логики к конкретным типам объектов. Используй единый базовый интерфейс `GardenObject` с полем `type`, от которого наследуются `Tree`, `Bed` и т.д.
- **Стейт (Zustand):** Проектируй store так, чтобы добавление новых полей в объекты не ломало существующую логику сохранения/загрузки.
- **Читай ROADMAP.md:** Перед реализацией любой новой фичи сверяйся с ROADMAP.md, чтобы понимать контекст и не создавать тупиковых архитектурных решений.

## Архитектура
- Компоненты: `src/components/` (группировать по папкам: Canvas/, Sidebar/, Toolbar/)
- Страницы (вкладки): `src/pages/`
- Store: `src/store/` (Zustand, один файл на домен: gardenStore.ts, uiStore.ts)
- Типы: `src/types/` (отдельные файлы на домен: tree.ts, bed.ts, garden.ts)
- Утилиты: `src/utils/`
- Хуки: `src/hooks/`
- Константы: `src/constants/`

## Библиотеки
- **Canvas**: Fabric.js (НЕ Konva, НЕ React-Konva)
- **State**: Zustand (НЕ Redux)
- **Стили**: TailwindCSS, CSS Modules
- **Иконки**: lucide-react
- **Роутинг**: react-router-dom v6
- **Формы**: react-hook-form (где нужны формы)

## Работа с Canvas (Fabric.js)
- Все объекты на canvas должны иметь кастомные data-атрибуты 
  (например, `objectId`, `objectType`, `year`)
- Сетка рисуется отдельным слоем, не участвует в выделении
- Фоновое изображение — самый нижний слой, при "замке" — `selectable: false`
- Масштаб canvas и масштаб схемы — разные вещи 
  (масштаб схемы влияет на пересчет метров в пиксели)

## Сохранение данных
- Формат .garden — это JSON, но с понятной структурой
- Каждый объект имеет `id` (crypto.randomUUID()), `type`, `year`, `history`
- История по годам: `history: { [year]: { harvest, rating, notes } }`

## Тестирование
- После каждого значимого изменения — запускай `npm run dev` и проверяй
- Если что-то сломалось — сначала почини, потом двигайся дальше
- Коммить в Git после каждой работающей фичи

## Приоритеты
1. Сначала рабочий MVP (canvas + объекты + годы + сохранение)
2. Потом полировка UI
3. Потом дополнительные фичи (дневник, отчеты)
